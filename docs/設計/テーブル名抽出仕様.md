# テーブル名抽出仕様（table_name_extractor.py）

対象: `backend/api/services/query_structure/table_name_extractor.py`

## 概要

`extract_table_names_with_alias(expression)` は、sqlglotでパース済みの1クエリブロック（`exp.Expression`）から、`FROM`句・`JOIN`句に登場する「直下の」テーブル名とエイリアスを `list[tuple[str | None, str | None]]` として抽出する。

QueryLensはSQLをサブクエリ単位の「クエリブロック」に分解して解析するため（`query_block_builder.py`）、この関数は **クエリブロック1つぶんの `FROM`/`JOIN` だけ** を見る。サブクエリの中身は別のクエリブロックとして個別に解析されるため、この関数の中では再帰しない。

## 戻り値の意味

各要素は `(table_name, alias)` のタプル。

| ケース | table_name | alias |
|---|---|---|
| 実テーブル（エイリアスなし） | テーブル名 | `None` |
| 実テーブル（エイリアスあり） | テーブル名 | エイリアス名 |
| サブクエリ | `None` | サブクエリに付けたエイリアス（なければ`None`） |
| `VALUES`句・`UNNEST`など、テーブルでもサブクエリでもないFROM対象 | 要素自体が結果から除外される |

## 具体例

### 1. 単純なテーブル + エイリアス

```sql
SELECT u.id FROM users AS u
```
→ `[("users", "u")]`

### 2. JOIN

```sql
SELECT * FROM A LEFT JOIN B ON B.test = A.test
```
→ `[("A", None), ("B", None)]`

`ON`句の中で参照されている `A.test` はカラム参照であり、`JOIN`が結合するテーブル本体（`join.this`）ではないため、`A`が二重に抽出されることはない。

### 3. JOINの相手がサブクエリ

```sql
SELECT * FROM A JOIN (SELECT * FROM C) B ON B.test = A.test
```
→ `[("A", None), (None, "B")]`

- `A`: 実テーブルなのでテーブル名のみ
- `B`: サブクエリ全体に付いたエイリアス。サブクエリ自体にテーブル名は存在しないため `table_name` は `None`
- `C`: サブクエリの中身（別のクエリブロック）なので、**この関数では抽出されない**。`C` は `query_block_builder.py` が `find_subquery_ranges` で切り出した別ブロックとして、`parent_alias="B"` を持つ形で個別に抽出される

### 4. FROM句がテーブルでもサブクエリでもない場合

```sql
SELECT * FROM (VALUES (1,2)) AS t(a,b)
```
→ `[]`

`(VALUES ...)` は sqlglot上 `exp.Values` というノードになり、`exp.Table` にも `exp.Subquery` にも該当しないため `(None, None)` を返す。`(None, None)` は情報を持たない無意味なエントリなので、`any(table_name_alias)` によるガードで結果から除外される。同様のケースとして `UNNEST(...)` などのテーブル値関数がある。

## 関連するテスト

`tests/services/query_structure/test_table_name_extractor.py`

- 単一テーブル（エイリアスあり/なし）
- 括弧で囲まれたクエリ
- JOIN（複数テーブル、エイリアス付き）
- サブクエリ（テーブル名がNoneになること）
- `VALUES`句（結果が空になること）

## 既知の制約・今後の検討事項

- `JOIN`の相手がサブクエリの場合、そのサブクエリの中のテーブル（上記例の`C`）はこの関数からは見えない。クエリブロック全体としては`query_block_builder.py`側で別ブロックとして解析されるため情報は失われないが、「この関数の戻り値だけを見ても全テーブルは分からない」という点は仕様として分かりにくい
- `VALUES`句・`UNNEST`などテーブルでもサブクエリでもないFROM対象は無条件に無視している。将来的にこれらの情報が必要になった場合は`_get_table_name_and_alias`の拡張が必要
