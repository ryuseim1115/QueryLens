# フロントエンドのイベントリスナー配置方針

対象: `frontend/js/pages/` 配下

## 結論

> 静的要素はentries/、動的生成要素は生成元のcomponents/モジュール自身がその場でリスナー登録する

`addEventListener` の登録場所は、**その要素がHTML内に元から静的に存在するか、JSで動的に生成されるか**で決める。

- **静的要素**（HTMLファイルに最初から書かれているボタン・inputなど）
  → その画面の`entries/*.js`（エントリーポイント）にリスナーを登録する。処理本体は`components/`側の関数として実装しexportし、entriesはそれを`addEventListener`の第二引数に渡すだけの「配線」に徹する。
- **動的生成要素**（`document.createElement`で作られる行・ボタンなど、entriesが読み込まれた時点ではDOMに存在しない要素）
  → 生成した`components/`側のモジュールが、生成のタイミングで自分でリスナーを登録する。entriesからは辿れないため。

## 判断基準

ある要素へのリスナーをどこに書くか迷ったら、次の問いで判断する。

> その要素は、画面のHTMLファイルに最初から書かれているか？

- Yes（静的） → `entries/`にリスナーを書く。componentは`export function handleXxxClick() {...}`のようにハンドラだけを提供する
- No（動的生成） → 生成元の`components/`モジュールが自分でリスナーを登録する

例:
- `input.html`の`.analysis-btn`（解析ボタン）・`.close-btn`（ダイアログの閉じるボタン）は、どちらも画面内の静的要素なので、リスナーは`entries/Input.js`に置く。`components/input/Analysis.js`は`handleAnalysisClick()`を、`components/input/FileDialog/DialogControl.js`は`closeDialog()`をexportするだけ
- `Result/Tables/createTableItem.js`が`document.createElement`で作るテーブル要素は動的生成なので、`createTableItem.js`自身がその場で`addEventListener`する

`<dialog>`配下の要素のように、画面の中の一部分だけを扱うUI部品であっても、静的要素である限りリスナー登録は画面の`entries/*.js`に集約する。「部品ごとに専用の配線ファイルを作って分割する」というやり方も検討したが、`entries/`フォルダはHTMLの`<script type="module">`が直接指す入口ファイルと1対1対応させておきたいため採用しなかった（部品専用の配線ファイルを`entries/`と同じ`components/`配下に置くと、`entries/`にある＝直接scriptタグから読み込まれる、という前提が崩れて紛らわしい）。`entries/Input.js`が肥大化する場合は、ファイル分割ではなくコメントで区切るなどで対応する。

## 補足: componentが同じ要素をqueryすること自体は問題ない

リスナー登録はentriesに一元化するが、component側がその要素を**読み書き**のために`document.querySelector`するのは問題ない（例: `UploadFile.js`が`.upload-file-btn`の`disabled`をアップロード中に切り替える、`Analysis.js`が`.analysis-btn`のラベルを差し替える、など）。避けたいのは同じ要素への**リスナーの二重登録・登録場所の分散**であり、状態の読み書きは実装上component側に置かざるを得ないことが多い。

## 例外: window宛のイベント

`window.addEventListener('message', ...)`のような、特定のHTML要素に紐づかないイベント（別ウィンドウとのpostMessage連携など）は、その通信を担うcomponentモジュール自身に置く。DOM要素の静的/動的の区別が適用できないため。

## 例外: 単一の関心事しか持たない画面

`entries/Login.js`・`entries/Register.js`のように、その画面全体が単一の関心事しか持たず、専用の`components/`ファイルが存在しない場合は、entries自身がロジックごとリスナーを書いてよい。
